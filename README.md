# 로이킴 공연일 올림픽공원 인구 수집

GitHub-hosted Linux에서 서울시 올림픽공원 인구 추정치를 1분마다 조회합니다. 서울시 자료 기준시각은 5분 단위이며 게시 지연이 있습니다. 뒷 구간 수집이 끝나면 회차별 그래프와 시간대별 CSV를 갱신합니다.

## 키 설정과 시험

1. 서울 열린데이터광장의 [서울시 실시간 인구데이터](https://data.seoul.go.kr/dataList/OA-21778/A/1/datasetView.do) 인증키를 발급받습니다.
2. 저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 이름을 `SEOUL_POPULATION_API_KEY`로 등록합니다. 키는 파일과 로그에 넣지 않습니다. 서울시 공식 API 요청 경로는 HTTP를 사용합니다.
3. **Actions → 로이킴 공연일 인구 수집 → Run workflow**에서 `check`를 선택해 올림픽공원 응답을 확인합니다. `sample`은 서울시가 공개한 광화문·덕수궁 샘플로만 연결을 확인합니다.

| 회차 | 앞 구간(KST) | 뒤 구간(KST) | 예약 시작(KST) |
|---|---|---|---|
| 2026-11-20 | 18:30–23:30 | 21:00–다음 날 02:00 | 18:13, 20:43 |
| 2026-11-21 | 16:30–21:30 | 19:00–다음 날 00:00 | 16:13, 18:43 |
| 2026-11-22 | 15:30–20:30 | 18:00–23:00 | 15:13, 17:43 |

회차별로 5시간씩 두 구간을 실행합니다. 두 구간은 2시간 30분 겹치고 작업 제한 시간은 350분입니다. 예약은 각 구간 시작 17분 전입니다. 예약 작업은 실행 시각에 수집 시작 30분 전부터 종료 직전까지 해당하는 구간 중 가장 늦게 시작하는 구간을 고릅니다. 해당 구간이 없으면 작업을 실패로 표시합니다. 일시적인 API 오류는 다음 분 조회까지 남은 시간 내에서 재시도합니다.

## 결과

Actions 실행 기록 하단의 Artifacts에서 `roykim-raw-…` 원본과 `roykim-report-…` 결과를 받습니다. JSONL의 `raw`에는 대체 여부, 혼잡도, 인구 비율과 예측값 등 서울시 응답 행 전체를 보존합니다. 결과에는 PNG, `REPLACE_YN`과 혼잡도가 포함된 CSV, 수집 범위표가 들어 있습니다. `report`로 결과를 다시 만들 수 있습니다.

집계는 첫 수집 시작 35분 전부터 마지막 구간 종료 직전까지의 기준시각을 포함합니다. 같은 기준시각은 마지막 조회값을 사용하고, 범위표는 이 구간의 5분 격자 대비 받은 고유 기준시각 수를 표시합니다. 마지막 일부 기준시각은 게시 지연으로 수집 종료 후 공개될 수 있습니다. 관측 간격이 5분을 넘으면 그래프의 선을 끊습니다. 인구는 공원 전체 추정치이며 실제 공연 종료 시각은 별도 관측이 필요합니다.
